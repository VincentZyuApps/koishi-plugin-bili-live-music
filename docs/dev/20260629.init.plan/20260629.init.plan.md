# bili-live-music init plan

## 目标

做一个 Koishi 插件：监听 B 站直播间弹幕，识别点歌指令，调用落月音乐 API 获取歌曲链接，维护播放队列，并通过 Koishi server 暴露 OBS 浏览器源页面播放音乐。

## 核心选择

- 形态：单个 Koishi 插件，不做 OBS 原生插件，不单独拆应用。
- B 站监听：通过 `w-node` 动态加载并锁定 `blive-message-listener` 版本。
- 默认监听库版本：`0.5.0`，写入配置项，允许用户手动修改。
- 播放方式：第一版只做 OBS 浏览器源 `<audio>` 播放。
- 暂缓：mpv / VLC 控制、复杂多平台 Restream 接入。

## 配置项规划

- `roomId`: B 站直播间号。
- `cookie`: B 站 Cookie，可选但建议填写。
- `uid`: 当前登录账号 uid，可选。
- `listenerVersion`: `blive-message-listener` 版本，默认 `0.5.0`。
- `commandPrefix`: 点歌前缀，默认 `点歌`。
- `apiBaseUrl`: 落月 API 地址。
- `enabledSources`: 启用的音乐源，如 `netease` / `tencent` / `kugou`。
- `maxQueueSize`: 最大队列长度。
- `perUserLimit`: 单用户队列限制。
- `cooldown`: 点歌冷却，单位秒，默认 25 秒。
- `overlayPath`: OBS 页面路径，默认 `/bili-live-music/overlay`。
- `wsPath`: OBS 页面 websocket 路径，默认 `/bili-live-music/ws`。

## w-node 使用方式

插件依赖 `node` 服务：

```ts
export const inject = ['server', 'node']
```

监听库加载：

```ts
const blive = await ctx.node.import<typeof import('blive-message-listener')>(
  'blive-message-listener',
  { version: config.listenerVersion, allowInstall: true },
)
```

这样可以把监听库安装到 `data/node` 下的独立版本目录，避免和同一个 Koishi 实例里的其他插件产生版本冲突。

## OBS 播放流程

1. OBS 添加浏览器源，打开 `http://127.0.0.1:<koishi-port>/bili-live-music/overlay`。
2. overlay 页面连接 `/bili-live-music/ws`。
3. Koishi 推送当前歌曲和队列状态。
4. 浏览器 `<audio>` 播放歌曲。
5. 播放结束后页面发送 `ended`，后端切到下一首。

## 第一阶段交付

- 配置项可在 Koishi WebUI 中编辑。
- 能连接指定 B 站直播间并接收弹幕。
- 能识别 `点歌 歌名`。
- 能调用落月 API 搜索并生成播放项。
- 能维护基础队列。
- 能通过 OBS 浏览器源播放队列歌曲。

## 后续阶段

- Koishi Console 队列管理页面：查看、删除、置顶、手动加歌。
- 黑名单、白名单、管理员跳过、用户冷却。
- 歌词/封面展示。
- mpv / VLC 播放后端。
- 监听库版本升级验证流程。

## 2026-07-17：Browser / VLC 双后端阶段

第二阶段将播放器从队列与 Overlay 中解耦，形成统一的 `PlaybackBackend` 接口。目录调整为：

```text
src/
  player/
    types.ts
    manager.ts
    factory.ts
    browser/
      backend.ts
      protocol.ts
    vlc/
      backend.ts
      process.ts
      rc-client.ts
      protocol.ts
  overlay/
    hub.ts
    protocol.ts
```

- `QueueManager` 只维护队列和播放状态，不再直接广播 WebSocket。
- `OverlayHub` 管理展示连接、Browser 主播放器角色和页面控制事件。
- Browser 后端通过唯一主页面播放音频；VLC 后端通过本地 TCP RC 控制插件专属进程。
- VLC RC 固定绑定 `127.0.0.1`，命令串行执行并拒绝 CR、LF 与 NUL 注入。
- VLC 3 的 TCP `oldrc` 没有稳定提示符，客户端使用串行命令与短暂静默窗口收集响应，同时兼容 VLC 4 提示符。
- 单曲加载失败跳过当前歌曲；VLC 进程或 RC 整体故障则保留当前歌曲和队列。
- 自动重启成功后当前歌曲从头播放，失败后等待管理员通过 WebUI 重启。
- 正式支持 Windows x64 VLC 3.0.18–3.0.23，VLC 4 nightly 作为实验支持。
